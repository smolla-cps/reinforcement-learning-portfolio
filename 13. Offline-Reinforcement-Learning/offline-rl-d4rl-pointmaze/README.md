# What Is This Dataset About?

The project uses:

```text
D4RL/pointmaze/medium-v2
```

The data come from the PointMaze Medium environment.

A **2-DoF point mass** moves through a closed maze. The controller applies continuous force in the Cartesian:

```text
x direction
y direction
```

The dataset contains previously recorded maze-navigation experience.

According to the notebook, the stored dataset contains:

- **1,000,000 fixed transitions**
- **4,752 stored episodes**
- goal-conditioned observations
- continuous two-dimensional actions
- sparse rewards

The behavior data were generated by following waypoint paths with added action noise, producing variation in the recorded trajectories.

The offline RL algorithms do **not** collect new transitions during training.

---

# What Is the Offline RL Agent Trying to Learn?

The objective is to learn a policy:

\[
\pi(s) \rightarrow a
\]

that answers:

> **Given the point's current state and desired goal, what continuous x/y forces should be applied so that the point navigates through the maze toward the goal?**

The complete goal-conditioned observation contains:

```text
observation
+
achieved_goal
+
desired_goal
```

The flattened state contains:

\[
4 + 2 + 2 = 8
\]

numeric features.

The continuous action is:

\[
a \in [-1,1]^2
\]

representing:

```text
force in x direction
force in y direction
```

Conceptually:

```text
current point position/velocity
        +
current achieved goal
        +
desired goal
        ↓
offline RL policy
        ↓
x force + y force
        ↓
movement through the maze
        ↓
closer to / reaches desired goal
```

The learned policy should maximize long-term reward while remaining grounded in the support of the fixed offline data.

# Observation Space

The PointMaze observation is goal-conditioned.

The notebook flattens the state in this fixed order:

```text
observation
→ achieved_goal
→ desired_goal
```

The resulting features are:

| Index | Feature |
|---:|---|
| 0 | Ball x position |
| 1 | Ball y position |
| 2 | Ball x velocity |
| 3 | Ball y velocity |
| 4 | Achieved-goal x |
| 5 | Achieved-goal y |
| 6 | Desired-goal x |
| 7 | Desired-goal y |

Therefore:

\[
\text{state dimension} = 8
\]

---

# Action Space

The action space is continuous with two components:

| Index | Action |
|---:|---|
| 0 | Linear force in x direction |
| 1 | Linear force in y direction |

Each component is bounded by the environment action space.

# Reward

The dataset uses a sparse reward.

As documented in the notebook:

```text
reward = 1  when the point is inside the goal region
reward = 0  otherwise
```

This makes the offline-learning problem challenging because successful reward signals are sparse.

# Method 1 — Implicit Q-Learning (IQL)

IQL is the primary offline-RL method in the project.

## Why IQL?

Offline RL has a major difficulty:

> A value function may assign high values to actions that are poorly represented or absent from the dataset.

IQL avoids explicit maximization over arbitrary unseen actions.

It learns:

1. twin Q-functions
2. a state-value function
3. a policy

The value network uses **expectile regression**.

The policy is extracted using **advantage-weighted behavior cloning**.

---

## IQL Pros

- designed for offline RL
- avoids explicit maximization over unseen actions
- natural fit for continuous action spaces
- suitable for D4RL-style datasets
- provides a strong conceptual link between value learning and behavior cloning

## IQL Cons

- sensitive to expectile and temperature settings
- still limited by dataset coverage
- sparse reward can make learning difficult
- neural training requires substantial computation
- training results may vary with random seed and training budget

# Method 2 — Conservative Q-Learning (CQL)

The second method is **CQL**, implemented with d3rlpy.

CQL attacks offline distribution shift differently from IQL.

## IQL

```text
Avoid explicit maximization over unseen actions.
Learn Q and V from logged dataset actions.
Extract the policy with advantage weighting.
```

## CQL

```text
Train a continuous actor/critic.
Add conservative regularization.
Reduce overly optimistic Q-values for poorly supported actions.
```

---

## CQL Pros

- designed specifically for offline RL
- directly targets Q-value overestimation
- widely used for D4RL-style continuous-control problems
- provides a meaningful contrast with IQL

## CQL Cons

- conservative regularization must be tuned
- too much conservatism can hurt performance
- computationally more demanding
- training is more complex than behavior cloning

# Evaluation

Training remains completely offline.

The recovered PointMaze simulator is used only after training for evaluation.

The notebook evaluates:

```text
Random Policy
IQL From Scratch

CQL with d3rlpy
```

using a common evaluation function.

The reported metrics include:

- average return
- return standard deviation
- average number of rewarding steps
- average final Euclidean distance to the desired goal

A stronger policy should generally produce:

```text
higher average sparse return
more rewarding steps
smaller final distance to goal
```
